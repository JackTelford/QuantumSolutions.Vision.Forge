# Schemas

The JSON Schema files in this directory are the source of truth for every document the CLI reads or writes: the CLI result on standard output, the tools manifest `doctor` writes, the render manifest next to a shot's frames, the brief, treatment, shot spec, look bible and job of a production, the assembly plan, the QA report and the assets ledger. `vocabulary.json` beside them holds every shared enumeration once (rule 16).

Two things are derived from them and must never be edited by hand:

- `src/shared/contracts/<kind>.ts`: TypeScript types generated by `npm run schema:gen` (`scripts/gen-types.ts`). `npm run schema:check` fails when the committed files are stale; CI runs it.
- The runtime validator `src/schema/validator.ts` loads every file here through `src/schema/schema-registry.ts` and validates documents with Ajv in draft 2020-12 strict mode.

`tests/schema/style-guide.test.ts` enforces rules 1–7, 10, 11, 12 and 14 on every schema file, plus the file-format part of 15 (`$schema` first, `kind` and `version` first, two-space indentation, LF, final newline), so a new schema that breaks one of them fails the test with the JSON pointer of the offending node. It checks that descriptions exist (5) and that hash properties (named `sha256`, `key` or `*Hash`) carry the pattern (11), not what the descriptions say. Rules 8, 9 and 13 and the rest of the key order in 15 are reviewed by hand. `tests/schema/vocabulary.test.ts` enforces rule 16.

## Rules

1. **Draft 2020-12 only.** `"$schema": "https://json-schema.org/draft/2020-12/schema"` is the first key of every file.
2. **One file per document kind**, named `<kind>.schema.json`, with `"$id": "https://vision-forge.quantumsolutions.dev/schemas/<kind>.schema.json"`. The kind is lowercase with hyphens (`render-manifest`).
3. **Root shape.** The root has `title` (PascalCase; it becomes the generated root type name, for example `RenderManifest`, and the generator refuses a schema without one), `description`, `"type": "object"`, and `required` whose first two entries are `kind` and `version`. `properties` starts with those two: `kind` is `{ "const": "<kind>" }` and `version` is `{ "type": "integer", "const": <n> }`. The registry refuses a file whose `kind` constant disagrees with its file name.
4. **Every object is closed.** Every object schema (`"type": "object"` or `["object", "null"]`) has `"additionalProperties": false` and lists `required` explicitly, even when it is `[]`. Every required name exists in `properties`.
5. **Every subschema has a `description`** that names its units (pixels, frames per second, seconds, bytes, hex characters, dots per inch) and its format where one exists, with an example value. The one exception is a bare `$ref`, which has no sibling keywords at all; the definition it points to carries the description. (json-schema-to-typescript inlines a `$ref` that has siblings instead of naming the type.)
6. **Enumerations live in `$defs`** under a PascalCase name, with `type` (`string` or `integer`), `enum` and `description`. Properties reach them through `{ "$ref": "#/$defs/<Name>" }`. Each one generates a union type `<Name>` and a value array `<Name>Values` that runtime code can list. `enum` is not allowed anywhere else.
7. **`$ref` is local.** Only `#/$defs/<Name>` within the same file; never another file or a URL, because the type generator cannot fetch them.
8. **Integers** use `"type": "integer"` with `minimum` where one applies (frame numbers, sizes, counts).
9. **Paths** are strings whose description says they are absolute.
10. **Timestamps** are `"type": "string", "format": "date-time"`: RFC 3339, written in UTC with millisecond precision (`2026-10-26T20:00:00.000Z`). `date-time` is the only format the validator implements; a new format needs an implementation in `src/schema/validator.ts` first.
11. **Hashes** are strings with `"pattern": "^[0-9a-f]{64}$"` (SHA-256, lowercase hex); the description says what was hashed.
12. **Nullable values** are `"type": ["<type>", "null"]` on the property itself, never `oneOf`/`anyOf` with a `null` branch, so a wrong value produces one error instead of three.
13. **Any JSON value** (the CLI result's `data`) is a schema that holds only a `description`. It validates anything; the generator maps it to `unknown`.
14. **Forbidden keywords**, because json-schema-to-typescript 16 ignores or mistypes them or Ajv strict mode rejects them: `prefixItems`, `$dynamicRef`, `$dynamicAnchor`, `patternProperties`, `minItems` and `maxItems` (they generate tuple types), `definitions` (use `$defs`), `nullable`, the generator's own `tsType`, and `title` anywhere but the root (the generator names a type after `title` before the `$defs` key, so `$defs.Colour` titled `Shade` would emit `type Shade` beside `ColourValues`).
15. **Key order** in a file: `$schema`, `$id`, `title`, `description`, `type`, `additionalProperties`, `required`, `properties`, `$defs`. Inside a property: `type`, `const`/`enum`/`format`/`pattern`/`minimum`, `description`, then `additionalProperties`, `required`, `properties` or `items`. Two spaces of indentation, LF line endings, a final newline.
16. **Shared enumerations come from `vocabulary.json`.** `schemas/vocabulary.json` maps a PascalCase name to `{ "type", "values", "description" }` for every enumeration more than one document or module relies on (`Lane`, `FrameRate`, `CameraMove`, `TransitionType`, `Codec`, `JobStatus`, ...). A `$defs` entry whose name is a vocabulary key repeats that entry's `type` and `enum` exactly, the same values in the same order, so `Lane` in `render-manifest.schema.json` and in `shot-spec.schema.json` cannot drift. Rule 7 still applies: a schema copies the values rather than referencing the vocabulary file. `tests/schema/vocabulary.test.ts` compares every schema against the file, checks that every vocabulary entry is carried by at least one schema, and keeps a list of known collisions (a same-named `$defs` entry that means something else) that fails once the collision is gone, so an exemption cannot outlive its rename; the list is empty, since `qa-report`'s subject kind is named `QaSubjectKind` for that reason. An enumeration that means something else must take another name. To add a value, change `vocabulary.json` and every schema that carries the name in one commit, then regenerate the contracts.

## Changing a schema

1. Edit the `.schema.json` file. A breaking change to a document that is written to disk (the tools manifest, a render manifest) bumps `version`; the reader decides what to do with older versions.
2. Run `npm run schema:gen` and commit the regenerated `src/shared/contracts/<kind>.ts` together with the schema.
3. Run `node --test "tests/schema/*.test.ts"`: the style guide, the validator examples and the drift check.

## Current kinds

| Kind | Written by | Read by |
| --- | --- | --- |
| `cli-result` | every command (`src/cli/result.ts`), on standard output | Claude, tests |
| `tools` | `doctor`, as `tools.json` under the data directory | every command that needs a program or browser |
| `brief` | the skill (Claude), from the user's prompt, as `brief.json` in the job folder | `plan`, `validate` |
| `treatment` | the skill, from the brief, as `treatment.json` in the job folder | `plan`, `validate` |
| `shot-spec` | the skill, from the treatment; `still` fills each shot's `renderProfile` at the gate (ADR 0004); as `shot-spec.json` in the job folder | `still`, `render`, `assemble`, `validate` |
| `look-bible` | the skill, as `look-bible.json` in the job folder | the lanes, the finishing module (`src/shared/grade/`), `qa`, `validate` |
| `job` | `plan`, as `job.json` in the job folder; updated by every later stage | `still`, `render`, `assemble`, `qa` |
| `assets-ledger` | `src/net/asset-ledger.ts`, as `assets.json` under the data directory | `assets`, the brief and shot-spec semantic checks |
| `assembly-plan` | `render`, from a job; tests, from synthetic clips | `assemble` |
| `qa-report` | `qa`, next to what it examined | Claude, `still` (the gate), tests |
| `render-manifest` | the render harness, as `manifest.json` next to a shot's frames | `render` (resume, cache validation), `assemble`, `qa` |

`validate <file>` checks any of these against its schema and then runs the semantic checks under `src/schema/checks/`, one file per kind, which cover what a schema cannot say (unique ids, frames inside a shot, text inside the title-safe area, WCAG contrast, assets present in the ledger).
